03 · INSTALL5分で立ち上がる

Requires Python 3.9+. MCPify 本体と生成CLIは標準ライブラリだけで動く。YAML の仕様書を読むときだけ PyYAML が要る（公開APIはYAMLが多いので入れておくのが無難）。

# clone and install
git clone https://github.com/imai-design/mcpify.git
cd mcpify
pip install -e ".[yaml]"

# run against any OpenAPI document
mcpify https://petstore3.swagger.io/api/v3/openapi.json --name petstore

# launch the generated MCP server
cd output/mcp_server
pip install -r requirements.txt
export MCPIFY_BASE_URL="https://your-api.example.com"
export MCPIFY_AUTH_TOKEN="your-bearer-token"
python server.py

Then drop the snippet from claude_desktop_config.example.json into ~/Library/Application Support/Claude/claude_desktop_config.json and restart Claude Desktop.

05 · SAFETY仕様書は「実行される入力」として扱う

MCPify は仕様書からコードを作る。つまり仕様書は、そのまま実行されうる入力だ。

  • コード注入を塞いだ — 仕様書由来の値はすべてエスケープしてから生成コードに埋める。細工したパラメータ名で任意コードが走る余地を残さない。
  • 内部ネットワークへ行かない — 仕様書URLがループバック・プライベート・リンクローカルを指していたら拒否する。公開URLから内部へ転送する手口も各リダイレクトで検証。--allow-local で開発時は解除できる。
  • 失敗が読める — 通信に失敗したらAPIのエラー本文と、次にやること（どの環境変数を設定するか）を表示する。
  • 壊れていないことを毎回確かめている — Python 3.9 / 3.11 / 3.13 でテスト12件＋実APIでの疎通確認をCIで自動実行。

07 · ROADMAP4チャネルから、もう一段深く

  1. OpenAPI → 4 channels · 今ここ。OpenAPI 3.x JSON/YAML を入力に、4チャネル同時生成。
  2. Framework route detection · Next.js / Django / Rails / Laravel のルート定義を直接読んで MCP 化。
  3. Playwright recorder mode · ソースが無い相手のアプリでも、ブラウザ操作を録画して MCP ツールに変換。
  4. Gatekeeper · OAuth2 / cookie-session プロキシ層。レート制御・監査ログ標準装備。
  5. TypeScript MCP server · 出力先を Python から TS に切替可能なオプション。
